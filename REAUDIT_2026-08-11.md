## 1. Headline: did the leak fix land?

**Yes. C-01 is genuinely fixed, in both channels, and the evidence is at the data level.**

### Channel 1 — the feature value

| Check | Baseline (`191e151`) | Now (`1e543bf`) |
|---|---|---|
| `snap_pct_off` non-null rows in `feature_matrix` | 125,425 | **0** |
| `snap_pct_off` in `FEATURE_COLS` | yes | no (and in `FORBIDDEN_MODEL_FIELDS`) |
| max same-game postgame equality, any feature column | **100.0000%** (`snap_pct_off` = `game_logs.offense_pct`, 125,425/125,425) | **45.2%**, and the pairing is nonsense (`kalman_est_rushing_tds` vs `rushing_fumbles`) |

I cross-compared **every** numeric `feature_matrix` column against **every** numeric `game_logs` column for
the same `(player_id, game_id)` — 129,128 joined rows — matched **by value, not by name**. This matters: the
original leak was a name mismatch (`snap_pct_off` ← `offense_pct`), so a name-matched check cannot find it.

Restricting to rows where either value is non-zero (which removes the zero-inflation artifact that makes
sparse count columns look identical), **no feature column reproduces a same-game postgame field.** The
residual 27–45% matches are all small-integer collisions between near-zero columns.

### Channel 2 — the cohort filter (the half everyone missed)

The `snap >= 0.34` filter is gone. `ml/utils.py:327` now filters
`df["seas_games_played"].fillna(0) >= MIN_PRIOR_GAMES` (=1). Proven pregame:

- `seas_games_played > count(prior games in season)`: **0.0000%** of 129,128 rows — it cannot include the
  target game.
- Week-1 rows with `seas_games_played > 0`: **0**.

### The replacement feature is a true lag

`prior_snap_share` replaces `snap_pct_off` and correlates 0.625 with PPR (the leaked column was 0.637), which
is close enough to warrant suspicion. It is clean:

```
prior_snap_share == prev_game offense_pct : 100.0000%  (n=111,935)
prior_snap_share == same_game offense_pct :  67.8325%  (n=111,933)
```

The 67.8% same-game figure is **exactly** the column's own autocorrelation baseline —
`P(offense_pct[t] == offense_pct[t-1]) = 0.6783` — driven by `offense_pct` being 0.00 in 78,392 of 129,128
rows. Fully explained; not a leak.

### The headline counts did move — and the count metric is weak either way

| Family | Reported pre-fix | Causal rebuild |
|---|---:|---:|
| fantasy_ppr | 20/20 | 4/20 |
| volume | 25/25 | 5/25 |
| passing | 5/5 | 1/5 |
| yardage | 24/25 | 5/25 |

The prompt said unchanged counts would be a red flag. They changed, dramatically, in the direction that
removing a 0.637-correlation feature should move them. **The edge is now small. That is the honest and
expected outcome, and it should be stated plainly rather than dressed up.**

Two cautions on that table:

1. `POST_LEAK_FIX_COMPARISON.md`'s "recomputed legacy OOF" column is **identical to the causal rebuild in all
   four families** (4/20, 5/25, 1/5, 5/25). The report attributes this to both columns using the same strict
   finite-baseline rule. That is plausible, and if true it means **the count metric is nearly insensitive to
   the leak** and is therefore weak evidence in either direction. The per-cell MAE table is the stronger
   evidence: MAE got *worse* on QB cells (5.74→6.28, 53.5→62.2) and *better* on WR/TE cells — a
   differentiated, non-uniform pattern consistent with a real rebuild.
2. **The machine-readable evidence in `reports/` still asserts the pre-fix counts.** See NEW-03. Only the
   prose file carries the honest number.

## 4. Attacks that failed — things I tried to break and could not

This section is deliberately as detailed as the findings. The original audit's credibility came from it.

1. **Name-mismatched leak hunt.** I cross-compared all 203 `feature_matrix` columns against all 42
   `game_logs` columns by value on 129,128 joined rows, specifically to catch a leak hiding under a
   different name (the shape of C-01). Nothing above 45%, and every high match is a small-integer collision.
   **No second leak found.**
2. **`prior_snap_share` as a disguised `snap_pct_off`.** Its 0.625 correlation with PPR is suspiciously close
   to the leaked column's 0.637, and it matches the same-game value 67.8% of the time. I could not make this
   a leak: it matches the *previous* game at exactly 100.0000% (n=111,935), and 67.8% is precisely the
   column's own lag-1 autocorrelation.
3. **Cohort filter smuggling target-game participation.** I tested whether `seas_games_played` could include
   the target game. It never exceeds the count of prior games (0.0000% of rows) and is 0 for every week-1
   row. **Clean.**

## 6. Ship verdict

# DO NOT SHIP for 2026 draft use.

This is a materially better tree than `191e151`, and the improvement is real rather than cosmetic — which is
worth saying plainly, because the prompt's prior was that the fixes would be cosmetic and on the decisive
finding that prior is wrong. **C-01, the finding the whole programme exists for, is genuinely closed, and I
proved it at the data level rather than taking the fixer's word.** So are C-02, C-03, C-04, C-05, C-06 — five
of the six P0 blockers. The draft output is now a prediction: the availability leak that dominated it fell
from ρ=0.926 to approximately zero.

It cannot ship anyway, for four reasons:

1. **NEW-01 — nothing can be served.** All 15 shipped coefficient artifacts fail the hardened loader. In
   artifact-backed mode every cell raises. The fail-closed behavior is correct and there is nothing behind
   it.
2. **Waves 04 and 05 were never delivered.** The gates that would justify a promotion decision (C-08) and
   the eval methodology that would make the numbers mean what they say (C-13) are untouched. The frozen
   baseline is still the candidate's own OOF, bit-for-bit. Three promotion records are still committed as
   `false`. **There is no mechanism in this tree capable of certifying a model as fit to ship.**
3. **NEW-03 — the tracked evidence still asserts the contaminated numbers.** The machine-readable summaries
   say 25/25 and 24/25. The honest answer is 5/25 and 5/25 and it lives only in prose. This is precisely the
   drift that C-29 named, recurring inside the remediation.
4. **Five cells are still never served (C-10) and the uncertainty is still a constant (C-11).** Exactly one
   distinct interval width per cell; zero posterior samples on 48,058 rows; hundreds of negative floors
   presented in percentile-named slots.

**And on the headline: the model edge is now small.** 4/20, 5/25, 1/5, 5/25 against strict finite baselines,
with MAE *worsening* on QB cells. That is the expected consequence of removing a feature with 0.637
correlation to the target, and it is the honest number. There is no longer a large claim to defend — which is
the right outcome, but it does mean the product's value proposition needs restating rather than reasserting.
